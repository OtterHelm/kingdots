# Minimal delivery scope

The goal remains actual Dots proactively supervising existing coding sessions.
Workers do not report to Dots, create supervisor sessions or invoke a separate
judgment model. Full automatic management requires real Dots observation,
judgment, safe intervention, fresh evidence and reporting after the initial reply.

## Current implementation

The local foundation includes explicit session registration, host/metadata reads,
quiet healthy observations, attention events, scoped instruction/receipt journals,
ownership epochs, intervention/restart fencing and dashboard controls.

Version 0.1.4 consolidates the existing request-driven PC transport into the main
service and canonical SQLite store. Returned judgments appear in the dashboard.
The remote account plugin still exposes only inspection and no-action review.
The unused PC OAuth gateway, standalone finite probe, duplicate local-plugin
installer, manual experiment runners, legacy worker manager, adapter execution
and worktree creation code are removed.
Historical records are retained; no paused watch is activated by migration.

## Current task boundary

The 2026-10-04 maintenance scope is quality within the existing structure, without
more providers, review scheduling or automatic control features. Finish accurate
documentation, transport/record correlation, packaging, controlled regressions,
Windows CI and installed-service/private-plugin upgrades.

Automated regression tests remain development tools rather than deployed test
functionality. Controlled fixtures and historical actual Dots evidence stay distinct.

## Remaining acceptance gates

Bounded actual Dots reads, judgment return and post-response one-time checks passed
on the preceding implementation. Retest the consolidated runtime with actual Dots.

Ongoing regular reviews, safe same-session instructions, five-minute urgent
response, unknown-host-send reconciliation and actual overnight management are
still unverified. A dashboard, webhook success or account-authenticated receipt
cannot replace these gates. No extra features are added to substitute for them.

Other products retain their individually unverified boundaries. Preserve original
work and paused watches. Keep both READMEs and interface/deployment/connection
documents aligned with source and [dated checks](verification-results.md).
